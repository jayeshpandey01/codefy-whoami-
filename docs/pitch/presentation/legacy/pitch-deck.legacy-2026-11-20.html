§ WHAT WE BUILD
Deterministic proof first. One narrow model question second. Never “audit this repository”.
01 · THE FOUNDATION
In-process AST
taint analysis
Dual engines (web-tree-sitter in WASM and ast-grep in N-API) build a concrete syntax tree of the live buffer, then propagate taint forward from untrusted sources (request body, query params, headers) and backward from sinks (exec, raw SQL, file ops, SSRF fetch).
<300 ms

02
Narrow-question triage
The engine extracts the exact taint path and program slice, then asks a single closed question: “does this guard sanitise this variable against CWE-89?” No open-ended discovery, so zero hallucinated drift.
03
Zero-data-leakage boundary
Shannon-entropy secret redaction, absolute-path anonymisation and AST slicing run before the gateway. Only a minimal 41 LOC slice (0.66% payload) is ever serialised into a prompt.
04
Multi-graph blast radius
Unified structural graph, control-flow graph and attack-surface DAG rendered in Cytoscape, React Flow, and Excalidraw formats, turning the exploit path into a visual picture rather than a paragraph in a PDF.
05
1-click verified remediation diff & Agentic MCP
Gemini 2.0 returns a surgical unified diff applied at the AST level. Shipped across VS Code, Tauri desktop, terminal CLI (codefy sast patch apply), and stdio MCP server for autonomous agent self-healing.
